# 0.63.0: both deep reviews worked off, a RED leg behind every fix

0.63.0 closes what the two 2026-10-20 deep reviews found and could be proved
on the rig: 19 of review 1's D-items and all of review 2's N1–N29 but N19.
Each fix had a leg that failed on the build without it (0.62.1, or the
commit before) and passes with it; every leg is registered in
`benchmarks/gate.py`. Per-item status tables are at the top of
`2026-10-20-deep-review.md` and `2026-10-20-deep-review-2.md`.

Upgrade if you run log_based (any lane), a MySQL or ClickHouse destination,
or the eager Arrow API on wide text.

## New refusals: runs that used to go green and are now stopped

These were silent divergences. Each one now fails before anything moves, and
the error names the way out.

| what | was | now |
|---|---|---|
| a Postgres CDC source table **dropped and recreated under its name**, then put back into the publication (apitap's own Postgres replace does this; N7) | the drain mapped the new table onto the old by name: green, the replace's rows never arrived | refused, naming the re-bootstrap. The source oid is recorded at bootstrap in `_apitap_source_rel` on the destination (an Iceberg table property). Pipelines bootstrapped earlier are adopted on their first 0.63.0 run |
| a MySQL **RENAME** onto or away from a tracked table, gh-ost/pt-osc cut-overs included (N16) | green, old rows kept | refused, naming the re-bootstrap |
| MySQL **data-changing DDL** on a tracked table: TRUNCATE/DROP/EXCHANGE PARTITION, DROP TABLE, DROP DATABASE, CREATE OR REPLACE, ALTER TABLE IF EXISTS, CONVERT, DISCARD/IMPORT TABLESPACE (D13, N5) | treated as schema-only, rows kept | refused |
| a tracked MySQL child of an **ON DELETE CASCADE / SET NULL** foreign key (N17) | the cascade is not in the binlog: green, cascaded rows kept | refused at resolve; `APITAP_MY_ALLOW_FK_CASCADE=1` opts out |
| a MySQL **replace that would drop** indexes, triggers, FKs, AUTO_INCREMENT, defaults or partitioning of a table apitap did not create (N24) | all of it gone | refused, naming them |
| a ClickHouse collapsing engine over `ORDER BY tuple()` on ch → ch (N26) | rows collapsed together | refused |
| a NULL in an Iceberg field the table declares REQUIRED (N27) | written | refused, bulk and CDC |

## Changed output

- **pg → mysql wide varchars** (N23): bounded `varchar(n)` columns stay
  `VARCHAR(n)` while the row has room, key columns first; the rest become
  `LONGTEXT`. Before, two `varchar(10000)` columns failed every run with
  ERROR 1118.
- **ch → ch replace** orders the new table by the source's sorting key (N26),
  and a multi-table run honours `order_by_per_table` everywhere (N12, D16).
- **ClickHouse append staging** is `CREATE … AS final`, so skip indexes and
  projections come along (N21).
- **Postgres append, merge and CDC apply** send `OVERRIDING SYSTEM VALUE` for
  ALWAYS identities and leave generated columns out (N20).
- **`to_parquet()`** sizes row groups from the engine's memory limit
  (`APITAP_MEM_BUDGET`, the process's own cgroup v1/v2) instead of the root
  `memory.max` (N29).

## Fixed failures

- **`to_polars()` / `to_arrow()` / `to_pandas()`** of a worker with more than
  2 GiB in one text column: refused "past i32 offsets" at any memory size;
  now the batch seals at 1 GiB (N28). Proof: 9M rows, 2.15 GiB in one column,
  `parallel=1`.
- **A quiet replication stream** (`wal_sender_timeout = 0`, or > 240 s, or a
  backlog of untracked WAL) died "silent for 120s … half-open". The client
  now asks for a keepalive every half budget (30 s at most) and calls the
  peer dead only when none is answered (N10).
- **MySQL destinations**: a loader session waits out a source slower than
  `net_read_timeout` (N22); the VARCHAR key cap is 3072 bytes in the column's
  own charset (N25); the key twin's load lets duplicate-key warnings through
  (N4); a delete + re-insert of one key in a window loads once (D2).
- **CDC replays**: the 0.62.0 journal key is still read (N1); a re-key with
  nothing journalled stops instead of skipping; a later move away from a key
  makes an earlier op on it moot (N3, D12); 0.62.x tombstone tables read
  back with FINAL (N2, D9).
- **Parallel reads into ClickHouse** keep NULL-cursor rows: the spans ask the
  source's nullability before the sink rewrites it (N6/N9, D30). This was a
  regression since 0.56.0: 900 of 1000 rows on a green run.
- **Postgres CDC bootstrap** pins `idle_in_transaction_session_timeout = 0`
  (and `transaction_timeout = 0` on PG 17+) on the walsender snapshot (N8,
  D31); the replication session pins `bytea_output = hex` (D33).
- **Parquet from Postgres**: `time` and `char` no longer match the MySQL
  type vocabulary (N18), which wrote raw micros into strings.
- **ClickHouse replace** drops past `max_table_size_to_drop` and drops staging
  only after the publish (D20); SharedMergeTree and Replicated databases are
  not counted as lossy (D21, unit test only).
- **Iceberg**: all-NULL cursor row groups are skipped at bootstrap (D22); a
  redirected commit is never read as a GET's 2xx (D23: only 307/308 are
  followed).
- **Others**: Postgres replace restore DDL keeps going past a failure (D24);
  S3/GCS stale-part sweep touches only its own parts (D25); ClickHouse
  source `int_pk` no longer picks a sorting-key column (D26); github JSON
  escapes survive NUL stripping (D27); MySQL YEAR 0000 (D29); text sources
  frame non-Nullable RowBinary cells (D32); an untracked TABLE_MAP clears
  its stale id (D14); `slots=N` bootstraps take turns (D18); changelog TOAST
  carry keys (D7).

## Correction to the 0.62.0 notes

The 0.62.0 notes said a ClickHouse replace without `engine=` "keeps the
engine of the table it replaces". It does not. Over a table with another
engine, PARTITION BY, a TTL or codecs, that replace is **refused**, naming
what would be lost; a plain MergeTree still replaces. Pass `engine=` to
rebuild on purpose. The 0.62.0 notes now say so.

## Gate

commit's tree (`e991bc4` plus the version bump), with the 0.55.1, 0.56.0,
0.62.0 and 0.62.1 upgrade legs and the GTID MySQL leg enabled:

- **188 passed, 0 failed, 17 skipped** of 205 legs, in 3306 s. 245 claim
  cells touched; **0 GAP** cells in the whole matrix.

  as 0.62.1's did.

  0.62.1 passes `cargo check` (lib, tests, and the Python crate) on its own.
