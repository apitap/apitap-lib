## Bench — speed is not reduced (single table)

Wheel under test: the final plain release build (no PGO this release).

- Writer paced at **36,544 changes/s = 2.19M changes/min** for 150 s.
- Drain kept up: **5,868,000 changes in 178.6 s ≈ 1.97M changes/min**, average
  **0.40 cores** (0.5 cap), **MEMPEAK 101 MB** (256 MB cap), ended empty
  (caught up), and the source↔destination digest **MATCHED**.

The shapes are not directly comparable: 0.58.0's recorded numbers are the
30-table GROUP at 0.5 CPU — 31,679 changes/s pure catch-up (**1.90M/min**),
~**1.50M/min** paced, one keep-up pass 1.71M/min, checksum-exact
(`benchmarks/cdc-steady-30t-0.58.md`). This 0.59.0 run is SINGLE-table; what
it establishes is that the wheel keeps up with a 2.19M/min writer on one
table at 0.40 cores with an exact digest — not a group comparison.

Residual: the 30-table group point is not re-measured. The drain hot path
changed only by a per-event timeout wrapper and a semaphore acquire (both
sub-microsecond), but the group number stands as the 0.58 record until a
group re-run happens.

## Residuals carried

- `APITAP_WINDOW_MAX_SECS` default stays 3600 s until the group measurement
  picks 10–30 s; the 30-table group bench (0.58: 1.90M/min catch-up,
  ~1.50M/min paced) is the first thing to re-run before any 3M/min claim.
- P1: the slot name is not yet stored in `_apitap_state` (adoption is by
  state presence).
- The vendored sqlx fork still exists (upstream 0.9 migration is a later wave).
- 30-table group bench pending.
