# 0.62.0 — the review release: 272 commits of correctness, no new lanes

Everything since 0.61.0 comes out of the line-by-line Rust review
(`docs/review/2026-10-15-MASTER-review.md`, the M-items) and the P2 sweep
(`docs/review/2026-10-18-p2-triage.md`). There is no new source or destination
and no headline speed number; what changed is what apitap does when a server,
a network, a type or a concurrent run behaves badly. Each fix landed with a
test that was seen to fail without it.

## Upgrade notes: defaults that changed

| change | what you see | how to keep the old behaviour |
|---|---|---|
| **TLS is verified by default off-loopback** on every Postgres pool (`af8569b`, `dc8bf4e`) and on the MySQL CDC lanes (`e5e1f49`) | a remote server without a trusted certificate now fails to connect, and the error names the opt-out | `sslmode=` / `ssl-mode=` in the URL, or `PGSSLMODE`; `ssl-ca=` points at your CA (`f555c58`) |
| a **replace into a table other tables reference** is refused before the load (Postgres `f117747`, MySQL `add4945`) | an error naming the foreign keys, not a half-done swap | drop or defer the FK first |
| **MySQL `LOAD DATA` warnings fail the run** (`0097dac`, M-20) | a duplicate key or truncated value is an error, not a silently short table | none: the old behaviour lost rows |
| **statement-format DML on a tracked MySQL table** is refused by the CDC lane (`0fd4b8e`, M-38) | the run stops and names the statement | `binlog_format=ROW` |
| **Iceberg writes format-version 2 tables only** (`69f63aa`) | a v1 table is refused by name | upgrade the table |
| a **ClickHouse user with `readonly=1`** is told it needs `readonly=2` (`e6c16b8`, M-53); every request pins the settings a profile could shorten an answer with (`335494b`, M-30) | a clear refusal instead of a wrong answer | `readonly=2` |
| a ClickHouse **replace without `engine=`** keeps the engine of the table it replaces (`f97aede`, M-29) | the replaced table keeps its ReplacingMergeTree / ordering | pass `engine=` to change it on purpose |

## What changed, by area

- **Every lane, every sink**
  - A parallel Postgres read pins one exported snapshot across all spans (`dee0818`, M-18).
  - The edge spans stay open, so rows committed during planning, and NULL cursors, are read (`47c46f9`).
  - A NOT NULL cursor's last span is a plain index range again: unreleased main between `47c46f9` and `a520d16` read 1.96x the source rows with `parallel=4`. No release shipped that, and this build reads 1.0x.
  - A flipped bootstrap never publishes destructively (`74caa8b`, M-11).
  - An exit or panic after prepare takes its staging back (`694e840`, `7893569`, M-33).
  - One table's panic in a multi-table run is that table's error (`66d391a`).
- **Postgres CDC:**
  - Mixed-case tables (M-60), INCLUDE columns, TOAST refetch through the primary key (M-59), and unchanged out-of-line keys taken from the old image.
  - Binary pgoutput is used only when every column has a renderer (M-7).
  - The control plane has deadlines.
  - Every run names other inactive apitap slots holding WAL (M-23).
- **MySQL / MariaDB CDC:**
  - The checksum follows each binlog file, and ROLLBACK discards (M-39).
  - Bytes reach bytea as hex, a DECIMAL keeps one spelling, and a zero TIMESTAMP is never 1970 (M-16, M-40, M-66).
  - `lower_case_table_names=1` works (M-44).
  - One transaction and one event are capped at `APITAP_TX_BUF_BYTES`.
  - Positions past 4 GiB are refused, not wrapped.
- **ClickHouse:**
  - A proxy 502/504 never repeats a statement that changes data (M-17).
  - Residue ops journal their image, so a replay is idempotent (M-12, M-13).
  - Only a `ReplacingMergeTree(_apitap_ver, _apitap_deleted)` takes the tombstone path (M-26).
  - A bootstrapped append records `mode=replace`, not a merge ClickHouse cannot run (`66a8fec`).
- **BigQuery:**
  - A job past the poll deadline is cancelled and settled.
  - CDC staging rotates over four tables.
  - A 308 resumes from what the session persisted.
  - Upload errors never print the session URI.
- **Object stores:**
  - A parquet publish never overwrites live parts (M-32).
  - S3 parts carry Content-MD5, and the final GCS chunk carries the object's CRC32C.
  - Throttles are retried with growing backoff.
  - Listings stop and have a page cap.
- **Iceberg:**
  - An ambiguous commit never sweeps its files, and stays unknown afterwards (M-14).
  - A commit refuses a schema or spec changed during the load.
  - An UNSIGNED cursor resumes (M-34).
- **Errors you can act on:**
  - A transport error says why it failed. Before: `error sending request for url (...600 chars...)`. Now: `operation timed out (APITAP_HTTP_READ_TIMEOUT=5s is a total deadline per request...)` (`e4e1156`).
  - URL errors never show a password.
  - An unsupported MySQL auth plugin is named with the fix (M-42).

New knobs:

| knob | does |
|---|---|
| `APITAP_WINDOW_DEPTH` | lets the drain run ahead of the applies |
| `APITAP_PARALLEL_APPLY=1` | applies proven insert-only windows concurrently |
| `APITAP_RUNTIME_WORKERS` | overrides the quota-derived worker count |
| `APITAP_HTTP_POOL_IDLE_MS` | idle lifetime of pooled HTTP connections |
| `APITAP_HTTP_REQUEST_TIMEOUT` | deadline for small control-plane requests, default 120 s |
| `APITAP_TX_BUF_BYTES` | the per-transaction and per-event cap |

## Honesty notes

- **Open from the deep review, and why:**
  - D10 (P1, new): the ClickHouse residue journal is keyed without the window's identity. Two verifiers upheld it from the code, but a fault-injection leg could not drive the stale entry into use, so it is not fixed blind.
  - D3, D4, D8 and D19: BigQuery, where nothing can run without a valid service-account key.
  - The remaining P1s were already in 0.61.0, and nothing in this release makes them worse. They are the 0.63.0 work list.

- **BigQuery was not run end to end for this release.** The service-account key on the
  bench rig is invalid, so every BigQuery leg skipped. The BigQuery changes above are
  covered by unit tests and fault-injection tests only. Treat BigQuery on 0.62.0 as
  unverified against the live service until those legs run again.
- Still open from the review:
  - R2-15 needs a two-node ClickHouse cluster to reproduce.
  - The BigQuery fence sweep and bq-lost-final-put need the live service.
- CI on GitHub is still only `publish.yml`. Unit tests and the gate run on the bench VPS
  before every push.
